# V1 验收清单

状态：待实现后执行；本文件不是测试通过报告。

## 资源和策略

- [ ] 干净安装不自动创建 A/B 组，不预设任何 GPT 或 DeepSeek 模型；原有 Key 行为不变。
- [ ] 可新建任意名称的第三、第四个组，绑定不同数量的任意 CPA 模型；套餐页面动态增加可配置行。
- [ ] 新增组默认没有套餐访问权；显式启用政策后才放行，且拥有独立账本和并发。
- [ ] 模型、供应商和凭证候选来自实际 CPA 配置，不把演示数组当成生产目录。
- [ ] 改组名保留 group_id、历史消费、套餐绑定；不存在按 A/B 名称分支的业务逻辑。
- [ ] GPT6 与 sol 唯一属于 A；luna 与 DeepSeek Flash 唯一属于 B。
- [ ] 单个模型重复归属两组时发布返回 409，指出冲突的组和模型。
- [ ] 大小写/前后空白采用既有规范化规则；不可擅自移除有业务意义的 prefix。
- [ ] 已发布成员不可在线更改；改组名称不改变 ID、账本和路由。
- [ ] 发布前预览未归组模型、已消失凭证、动态类别选择和最终权限交集。
- [ ] Group 列表仅使用虚构模型 ID 测试；实际模型从 CPA 获取。
- [ ] 多套餐引用同一资源组，分别设置不同额度，互不覆盖。
- [ ] 金额 null 与并发 null 表示不限，0/负值输入被拒绝。

## 金额与账期

- [ ] 用户甲 A 已用 $490、B 已用 $800：两个组分别剩余 $10、$200。
- [ ] GPT6 再消耗 $6、sol 再消耗 $4：A 达 $500，后续 A 拒绝，B 仍可用。
- [ ] 用户乙仍拥有自己的 $500/$1000。
- [ ] B 金额改为不限后仍继续记账；恢复 $1000 时计入此前当天消费。
- [ ] Asia/Shanghai 23:59:59 发起、次日完成的 usage 只计入前一天。
- [ ] 已经切换到新日后上报的旧请求，旧账本得到更新且新账本不变。
- [ ] 重启保留账本，显示没有重复领取额度。
- [ ] 套餐额度变更保留已用金额；套餐切换不创建第二个相同日额度。
- [ ] 重置保留原始消费与审计；重置前开始、重置后到达的 usage 不扣新额度。
- [ ] 有用量的失败请求遵守既有计费口径，并在失败事件可查询。
- [ ] 无用量/无价格记录保留且标记金额不完整；报表不宣称费用完整。
- [ ] nano-USD 转换覆盖极小费用、上界、非有限值、负值和溢出。
- [ ] 已在途请求可导致超额，报表展示准确；未承诺严格预付费。
- [ ] usage 缺少 RequestID 时不使用模型/时间拼接为去重或准入关联主键。
- [ ] 数据库写入失败被明确暴露，不能继续无限放行受影响的分组。

## 并发与路由

- [ ] 同 Key 同时 GPT6+sol 占 A 两个槽，第三个 A 返回 group_concurrency_exceeded。
- [ ] A 已满时 B 仍可进入；B 进行中的请求不会占 A 的槽。
- [ ] 用户甲的 A 槽不会限制用户乙。
- [ ] 相同 RequestID 重复准入不重复占槽；重复 complete 不出现负计数。
- [ ] 成功、失败、取消、流式中断、准入期间异常都释放正确的槽。
- [ ] B 并发不限时仍统计，降低限制后已在途不被强制打断。
- [ ] CPU 多线程争抢槽位测试不超过上限，运行 race 检查。
- [ ] 组凭证池与 Key 原权限做交集，组内 allow 不得覆盖 Key 的 deny。
- [ ] 供应商整类选择包含新增凭证，固定列表不包含新增凭证。
- [ ] 无允许的上游凭证返回 503，不切换到别的计费组。
- [ ] 目标 CPA 的 RequestedModel/Alias 在各协议与重试中保持可确定归组。
- [ ] 同一上游模型不同别名、内部 helper、跨日期迟到事件全部实测，不能猜测归属。

## Keeper 与访问权限

- [ ] 下游 Key 对应 key_alias，上游身份对应 alias，CPA note 为独立只读展示。
- [ ] Keeper 改名后计费刷新显示；计费改名后 Keeper 刷新显示。
- [ ] 空 alias 同步为清空，不回退到旧标签。
- [ ] 两个有相同脱敏预览或相同备注的 Key 不混淆。
- [ ] 原始 API Key、管理员密码和 Cookie 不落日志/SQLite/计费前端。
- [ ] Keeper URL 带子路径时 API 拼接正确。
- [ ] session 过期只尝试一次重新登录；403 不通过关闭认证绕过。
- [ ] 外部修改与本地草稿冲突时提示刷新；明确不承诺跨 Keeper 页面的原子 CAS。
- [ ] 404/已删除对象不会用过期 ID 覆盖另一个对象。
- [ ] Keeper 不可达：显示最近成功标签及过期提示，计费与限流仍正常；保存不报告成功。
- [ ] 保存成功后回读；回读失败的状态可与写入失败区分，避免无意重复提交。
- [ ] 普通 Key 无法修改备注/计划，查询参数无法选择其他人的 scope。
- [ ] 普通账户不返回上游内部 alias/note；备注包含 HTML 时仅作为文本显示。
